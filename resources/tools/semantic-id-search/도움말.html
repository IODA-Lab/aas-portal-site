시작 절차

기본 작업 절차

사전 연결 → 항목 검색 → 의미 비교 → IRDI 활용

항목 제목을 선택하면 상세 설명이 표시됩니다.

01 ECLASS 사전 연결사전 폴더 또는 사전 ZIP을 한 번 연결합니다.

‘사전 폴더 연결’에서 자료가 있는 폴더를 선택합니다. 폴더 이름은 자유롭습니다. ‘사전 파일 가져오기’에서는 ZIP·개별 XML·BASIC 속성 CSV를 선택할 수 있습니다. 기본값인 ‘전체 통합’은 선택한 폴더/ZIP 안의 ADVANCED·ASSET·BASIC을 함께 읽습니다. 한 종류만 필요하면 자료 종류를 직접 선택합니다.

최초 가져오기는 수 분이 걸릴 수 있습니다. 진행 상태를 확인하며 대기합니다. 이후에는 저장된 로컬 사전으로 검색합니다. 원본 파일은 변경하지 않습니다.

사전 폴더 경로 및 구성위치·이름은 자유롭게 지정합니다. 여러 사전을 포함하는 상위 폴더를 선택합니다.

경로 지정: 사전 폴더의 위치와 이름은 자유롭게 지정할 수 있습니다. C드라이브·D드라이브 등 접근 가능한 위치를 선택하며, 특정 경로나 sources라는 폴더 이름은 필수 조건이 아닙니다. 다른 PC에서도 해당 사용자가 지정한 폴더를 연결합니다.

폴더 준비: 아래 예시는 C:\ECLASS자료를 사용하지만, D:\표준사전 등 다른 위치로 변경할 수 있습니다. 같은 ECLASS 버전의 ADVANCED·ASSET·BASIC 자료를 한 상위 폴더 아래에 모읍니다. 하위 폴더 이름도 자유롭게 정하며, 배포 자료의 내부 구성과 함께 제공된 단위·분류 파일은 그대로 유지하는 것이 좋습니다.

선택 절차: ‘새 사전 연결 설정 → 전체 통합 → 사전 폴더 연결’에서 세 자료 폴더를 포함하는 상위 폴더를 선택합니다. 프로그램이 그 아래 하위 폴더의 사전 파일도 찾습니다. 예시에서는 C:\ECLASS자료를 선택합니다.

ZIP 처리: 선택한 상위 폴더에 사전 ZIP만 있거나 ZIP 안에 ZIP이 있는 경우에는 먼저 압축을 풀어 XML·CSV 사전 파일이 폴더 안에 있도록 준비합니다. XML·CSV가 직접 들어 있는 사전 ZIP은 ‘사전 파일 가져오기’로 연결할 수 있습니다.

검색 범위: 선택한 위치에 있는 자료만 검색합니다. ASSET 자료만 있으면 전체 통합을 선택해도 ASSET만 연결됩니다. 연결 후 ‘현재 검색 사전’에서 실제 포함된 종류를 확인합니다. 아래 파일 설명은 구성 예시이며, 같은 이름의 빈 파일이나 폴더를 만드는 것으로 사전이 준비되지는 않습니다.

02 검색 항목 입력미등록 한국어도 자동 해석합니다. 결과의 ‘입력 → 검색’을 확인합니다.

‘제조사명’, ‘공정 온도 상한’처럼 한국어 또는 영문 항목명으로 검색합니다. 전체 IRDI를 입력하면 그 ID를 정확하게 조회합니다. 기본 용어표에 없는 한국어는 내장 모델이 영문 검색어로 해석합니다. 예: 깊이 → depth, 압력강하 → pressure drop. 처음 해석하는 표현은 수십 초 걸릴 수 있으며 검색 중 취소할 수 있습니다. 결과 위의 ‘입력 → 검색’을 확인하고 의도와 다르면 영문으로 수정합니다. AI가 IRDI를 만드는 것은 아니며 후보는 연결한 사전에서만 찾습니다.

‘적용 조건 입력’에서 장비, 대상·위치, 값의 역할을 지정합니다. 단위·데이터형·설명도 함께 입력할 수 있습니다.

03 후보의 의미 비교후보의 정의와 단위가 실제 데이터와 맞는지 비교합니다.

목록에서 후보를 선택하고 오른쪽의 원문 정의를 확인합니다. 명칭이 비슷해도 측정 대상·단위·값의 성격이 다르면 같은 속성이 아닐 수 있습니다. 검색 순위만으로 확정하지 않습니다.

04 결과 활용후보 선택 → 이 IRDI로 확정 → 검토자·근거 입력 → 이력 저장

후보를 선택하고 오른쪽 아래 ‘이 IRDI로 확정’을 선택합니다. 검토자와 선정 근거를 입력한 뒤 ‘확정하고 저장’을 누르면 ‘확정 이력’으로 이동합니다. IRDI만 필요하면 ‘IRDI 복사’를 사용할 수 있습니다. 여러 항목은 ‘엑셀 일괄 검색’으로 검토용 후보 파일을 만들 수 있습니다.

검색어 자동완성‘제’ 입력 → 제조사명·제조날짜 추천 → 선택 후 검색

검색창에 ‘제’를 입력하면 제조사명·제조날짜 등의 검색어가 아래에 표시됩니다. 마우스로 선택하거나 아래/위 화살표와 Enter를 사용합니다. Esc로 추천을 닫습니다. 추천 목록에 없어도 한국어 항목명을 입력하고 검색할 수 있습니다. 추천어는 검색을 돕는 용어이며 사전 속성과 일치한다는 뜻은 아닙니다.

사전 구성 및 활용 기준

표준 속성의 뜻을 검토한 후, 자료 종류별 구성과 적용 범위를 확인합니다.

항목 제목을 선택하면 상세 설명이 표시됩니다.

① BASIC · 제품 속성을 한 단계의 목록으로 표현제품 속성을 한 단계의 목록으로 제공하며, 구매·판매·관리 업무에 활용합니다.

제품을 설명하는 속성을 한 단계의 목록으로 제공합니다. 제품 정보를 표로 관리하거나 구매·판매·관리 시스템에서 활용하기에 적합합니다.

BASIC과 ADVANCED는 같은 제품 분류 체계를 사용합니다. 차이는 주로 분류된 제품에 연결되는 속성의 범위와 구조입니다.

BASIC은 ADVANCED 내용 중 일부를 단순한 구조로 제공하며, 공식 문서에서는 ADVANCED의 부분집합으로 설명합니다.

BASIC은 CSV와 XML로 제공됩니다. BASIC CSV는 표준 사전 자료이며, 사용자가 검색할 항목을 적는 일괄 검색용 엑셀과는 용도가 다릅니다.

② ADVANCED · 속성의 묶음·중첩·반복 지원속성의 묶음·중첩·반복을 지원하며, 상세한 설계·엔지니어링 정보에 활용합니다.

복잡한 제품 특성을 상세하게 표현하기 위해 속성을 묶고, 묶음 안에 다른 묶음을 배치하거나 필요한 만큼 반복할 수 있습니다.

Block — 관련 있는 속성을 하나의 묶음으로 구성합니다. 예를 들어 정격 전압과 정격 전류를 전기 특성이라는 주제로 묶을 수 있습니다.

Aspect — 특정 상황이나 관점에 해당하는 속성을 묶습니다. 클래스의 최상위에 배치되는 특별한 형태의 블록입니다.

Cardinality — 필요한 개수만큼 블록을 반복할 수 있습니다.

Polymorphism — 조건에 따라 블록의 구체적인 유형이나 내용을 선택할 수 있습니다.

이러한 계층 구조는 상세한 기술 정보 표현에 적합하며, 구현은 BASIC보다 복잡합니다. 주로 설계·엔지니어링과 컴퓨터 지원 설계·제조 분야에서 활용합니다. XML로 제공됩니다.

전기 특성 예시는 구조 이해를 위한 설명이며 실제 ECLASS 분류 경로를 뜻하지 않습니다.

③ ASSET · AAS 서브모델 구성 지원AAS 서브모델에 필요한 ECLASS 속성을 Aspect별로 구성합니다.

AAS(자산관리셸)는 장비·제품의 정보를 표준 방식으로 표현하는 체계입니다. 서브모델은 디지털 명판이나 기술 데이터처럼 하나의 주제로 구분한 정보 영역입니다.

ASSET은 AAS 서브모델에 필요한 ECLASS 정보를 모아 XML로 제공합니다. 핵심은 Asset Application Class, 즉 ‘Asset 유형의 응용 클래스’입니다.

이 클래스에는 AAS 서브모델에 대응하는 Aspect가 들어가며, 각 Aspect에 해당 서브모델에 필요한 ECLASS 속성들이 연결됩니다. ADVANCED의 내용을 AAS에서 활용하기 쉽게 구성한 것입니다.

아래 표는 대표적인 서브모델과 담는 정보의 예시입니다. 실제 제공 범위는 ECLASS 릴리스에 따라 달라지므로 연결할 자료의 릴리스 설명을 함께 확인합니다.

ASSET XML 자체가 특정 장비의 실제 값까지 채워진 완성 AASX 파일이라는 의미는 아닙니다.

지원 범위: 후보 상세에서 수록 자료 종류와 내용 차이를 확인할 수 있습니다. 현재 프로그램은 속성 검색·비교를 지원하며, ADVANCED의 모든 연결 관계를 해석하거나 ASSET으로 AASX를 생성하지는 않습니다.

중복 기준: 같은 속성이 여러 자료 종류에 수록될 수 있습니다. 전체 IRDI와 끝의 개정 번호가 모두 같으면 하나의 후보로 통합합니다. 개정 번호가 다르면 별도 후보로 유지합니다.

검증 사례: 현재 확인한 ECLASS 16.0 영문 자료는 ADVANCED 37,021개, ASSET 570개, BASIC CSV 23,093개입니다. ASSET·BASIC의 IRDI가 ADVANCED에도 포함되어 있어 통합 후 고유 속성 수는 37,021개입니다.

적용 범위: 위 수치는 확인한 자료의 결과입니다. 다른 버전이나 자료 구성에서는 달라질 수 있습니다.

속성 · 클래스 · 원문 정의속성은 개별 특성, 클래스는 분류, 정의는 정확한 의미입니다.

속성(Property)은 제조사명이나 온도 상한처럼 개별 특성을 설명합니다. 클래스(Class)는 분류나 설명 구조를 구성합니다.

원문 정의(Definition)는 속성이 정확히 무엇을 뜻하는지 설명합니다. 이 프로그램의 주 검색 대상은 속성이며, 클래스 검색 도구는 아닙니다.

Preferred name · Short namePreferred name = 표준 명칭 / Short name = 사전에 있는 약어

Preferred name은 사전에 수록된 표준 명칭이며 후보 제목으로 표시됩니다. 한국어 검색어를 번역해 만든 이름이 아닙니다.

Short name은 사전에 수록된 약어입니다. 약어가 없는 경우에는 ‘사전에 약어 없음’으로 표시합니다.

한국어 정의XML 한국어 원문 / 보완 번역 / 자동번역을 구분해 확인합니다.

원문 정의 아래의 ‘XML 원문’ 표시는 사전에 수록된 한국어 정의입니다. ‘자동번역 / 검토용’ 표시는 영어 정의를 PC의 번역 모델로 번역한 참고 문장입니다. 공식 ECLASS 번역이 아니므로 전문 용어·수치·조건은 원문과 비교합니다. 번역으로 검색 순위나 원본 사전을 바꾸지 않습니다.

큰 오프라인 모델로 번역하므로 새 정의는 수십 초 이상 걸릴 수 있습니다. 번역 중에도 검색할 수 있습니다. 개별 검색은 선택한 후보를 번역하며, 일괄 검색은 출력할 후보의 정의도 번역합니다. 같은 정의는 PC에 저장한 결과를 재사용합니다. 원문 전체가 일치하는 내장 참고 번역이 있으면 ‘보완 번역 · 검토용’으로 구분합니다. 모델이나 번역 지침이 바뀌면 이전 정의 번역 캐시는 재사용하지 않습니다. 사전과 확정 이력은 유지합니다.

원문의 구조가 불명확하거나 해석을 보류한 경우에는 ‘원문 확인 필요’로 표시합니다. 표준 명칭과 영문 정의를 함께 확인합니다.

단위와 데이터형단위는 °C·bar, 데이터형은 문자열·정수·실수 등의 형식입니다.

단위는 °C, bar처럼 값의 크기를 해석하는 기준입니다. 데이터형은 문자열·정수·실수처럼 값의 형식을 나타냅니다.

단위가 같아도 의미가 같다는 뜻은 아닙니다. 예를 들어 현재 온도와 허용 최고 온도는 모두 °C일 수 있지만 서로 다른 정보입니다.

자체 IRI표준에 맞는 항목이 없는지 검토한 뒤 기관 기준을 따릅니다.

표준 사전에서 적합한 항목을 찾지 못한 경우 기관의 작성 기준에 따라 관리하는 식별자입니다. 현재 연결한 사전에서 후보가 없다는 이유만으로 바로 만들어서는 안 됩니다. 이 버전은 자체 IRI를 생성하지 않습니다.

신규 모델의 사용 제한

기존 모델의 의미를 확인하기 위한 조회용 속성입니다.

사용 중단 속성의 정의사용 중단 = 새 모델에 사용하지 않도록 지정된 속성

ECLASS에서 해당 버전의 신규 사용을 중단한 속성입니다. 다른 속성으로 대체되거나 철회된 경우가 있습니다.

과거 모델의 ID와 의미를 해석할 수 있도록 XML 사전에는 남아 있습니다. 파일이 깨졌거나 프로그램이 임의로 삭제한 항목이라는 뜻은 아닙니다.

검색 및 표시 기준기본 검색에서 제외되며, 포함 옵션이나 정확한 IRDI로 조회합니다.

기본 검색에서는 제외합니다. ‘사용 중단 포함’을 켜거나 전체 IRDI로 정확히 검색하면 ‘사용 중단 · 조회용’ 표시와 함께 볼 수 있습니다.

신규 모델에는 사용하지 않도록 안내하는 표시입니다. 기존에 저장된 이력은 변경하지 않습니다.

기존 모델의 사용 중단 속성 처리기존 ID를 바로 바꾸지 말고 당시 정의와 공식 대체 관계를 확인합니다.

기존 ID를 즉시 삭제하거나 비슷한 이름의 속성으로 자동 교체하지 않습니다. 당시 사전 버전과 원문 정의를 확인하고, 공식 변경·대체 관계가 있는지 검토한 후 변경합니다. 후속 속성이 반드시 존재하는 것은 아닙니다.

사용 중단 여부의 확인 범위현재 표시는 속성 자체의 사용 중단 여부를 확인합니다.

현재 버전은 속성 자체의 is_deprecated=true 표시를 읽습니다. 특정 클래스와 속성의 연결, 데이터형·단위·값목록 등의 적용 조건별 사용 중단까지 모두 판정하는 기능은 아직 없습니다. ‘사용 중단 표시 없음’이 모든 적용 조건에서 사용 가능하다는 보증은 아닙니다.

측정값·설정값·허용한계값의 구분센서값·운전 목표·허용 한계는 서로 다른 데이터입니다.

분무건조기 / 입구 공기 / 측정값: 입구 센서에서 측정한 현재 온도.

분무건조기 / 건조실 공기 / 설정값: 제어기에 입력하는 운전 목표 온도.

분무건조기 / 공정 공기 / 허용한계값: 장비가 허용하는 온도 한계.

장비가 달라도 의미가 같다면 같은 Semantic ID를 사용할 수 있습니다.

판정과 검색 순서의미 충돌이 있는 후보는 뒤로 표시합니다. 최종 적합성은 원문을 기준으로 판단합니다.

속성 이름과 정의의 제한된 표현 규칙으로 역할·대상·위치를 비교합니다. 역할, 입구/출구, 물리량, 후보 이름에 명시된 장비 범위 등이 충돌하면 감점하고 충돌 없는 후보 뒤에 표시합니다. 전체 IRDI 정확 조회는 충돌이 있어도 해당 항목을 보여 줍니다.

이 기능은 의미 적합성을 보증하는 AI나 표준 검증기가 아닙니다. 지원하지 않는 표현, 복합 조건, 부정문은 직접 검토합니다.

적용 조건 판정의 해석일부 부합 = 나머지 검토 / 근거 부족 = 직접 비교 / 보완 필요 = 정보 입력

적용 정보 보완 필요: 입력 정보 부족. 필요한 적용 조건을 보완하고 다시 검색해 후보의 의미를 비교합니다.

적용 조건 불일치 · 재검토: 입력과 후보 또는 입력 정보 사이에 다른 의미가 감지됨. 사유를 확인합니다.

적용 여부 확인 필요: 입력은 있지만 사전 표현만으로 역할·대상·위치를 확인하지 못함.

일부 조건 부합 · 최종 검토 필요: 자동 규칙에서 일부 표현이 일치함. 정답 판정이 아니며 원문 검토가 필요합니다.

장비 분류의 입력 및 비교 범위확인한 클래스 이름이 있을 때 입력합니다. 자동 장비 분류는 아닙니다.

확인한 ECLASS 장비 분류의 이름이 있으면 ‘장비 분류명’에 입력합니다. 현재 적재된 직접 연결 클래스 이름과 정확히 비교합니다. 클래스 IRDI나 분류 코드를 검증하는 기능은 아닙니다.

장비명으로 찾은 클래스 단어 일치는 참고 근거만 됩니다. 연결 정보가 없다고 부적합으로 제외하지 않습니다. 클래스 상속 관계는 전개하지 않으므로 최종 적용 범위는 원본 사전에서 확인해야 합니다.

역할 자동 추정과 검토역할을 비우면 일부 표현에서 추정합니다. 추정 결과도 확인합니다.

역할을 비우면 항목명·설명의 ‘현재’, ‘상한’, ‘설정’ 같은 표현에서 추정할 수 있습니다. 추정한 역할과 입력한 역할이 다르면 충돌을 표시합니다.

대상·위치는 자유 입력이며 자동 비교할 수 있는 용어가 제한적입니다. 미확인 후보는 원문과 실제 데이터의 관계를 직접 비교합니다. 입력 적용 조건과 판정 내용은 엑셀 일괄 검색 결과에 함께 저장됩니다.

항목 제목을 선택하면 상세 설명이 표시됩니다.

검색 순위의 의미1위·2위·3위는 이번 검색의 후보 순서입니다. 1위가 정답이라는 뜻은 아닙니다.

검색 결과를 1위·2위·3위 순서로 표시합니다. 입력 용어와 사전 속성의 관련성, 적용 조건을 반영한 이번 검색의 후보 순서입니다. 1위라고 정답이거나 사용이 확정된 것은 아닙니다. 검색어·적용 조건·사전이 바뀌면 순위도 달라질 수 있습니다.

적용 조건 상태와 주의사항후보 카드의 적용 조건 상태와 오른쪽 주의사항을 함께 확인합니다.

후보 카드에는 ‘적용 정보 보완 필요’, ‘적용 조건 불일치 · 재검토’, ‘적용 여부 확인 필요’, ‘일부 조건 부합 · 최종 검토 필요’ 등이 표시됩니다. 자세한 기준은 ‘장비 · 대상 · 값의 역할’ 도움말을 확인합니다.

오른쪽 주의사항에는 단위·데이터형과 의미 차이도 함께 표시됩니다. 경고가 없다고 정답이 보장되지는 않습니다.

현재 공정 온도 ≠ 공정 온도 상한단위가 같아도 측정값과 허용한계값은 서로 다른 의미입니다.

‘현재 공정 온도’는 센서에서 측정한 현재 값입니다. ‘upper limiting value of process temperature’는 장비가 견딜 수 있는 온도 상한을 뜻합니다.

단어와 단위가 비슷해도 의미가 다르므로 같은 ID로 연결하면 안 됩니다. 검색 예제에서 두 항목을 비교할 수 있습니다.

검색 후보가 없는 경우의 확인 절차해석된 검색어 → 짧은 핵심어 → 사전 버전·포함 범위 순으로 확인합니다.

해석된 검색어로 현재 연결한 사전에서 찾지 못한 상태입니다. 검색어 해석 실패는 사전에 후보가 없는 경우와 별도로 표시됩니다. ECLASS 전체나 다른 표준에도 없다는 의미는 아닙니다.

① 영문 항목명으로 검색 → ② 핵심 단어로 줄여 검색 → ③ 사전 버전·포함 범위 확인 → ④ 필요한 추가 사전에서 검토 순서로 진행합니다.

검색 근거와 적용 조건일치 키워드는 검색 근거이며, 장비 적용성을 보증하지 않습니다.

검색 결과의 일치 키워드와 실제 검색어, 오프라인 AI 해석 여부를 확인할 수 있습니다. 장비명과 설명은 검색 보조 정보이며, 장비에 실제로 적합한지는 자동 검증하지 않습니다. 클래스 목록은 직접 연결된 이름을 최대 100개 보여 줍니다. 관계 전체를 전개한 결과는 아닙니다.

단순히 ‘1순위라 선택’이라고 적기보다 정의와 현장 데이터가 연결되는 이유를 기록합니다.

입력 조건 변경 후 재검토조건을 바꿨다면 다시 검색하고 후보와 주의사항을 확인합니다.

검색 조건이나 적용 조건을 수정했다면 다시 검색해 후보와 주의사항을 확인합니다.

확정과 이력 저장확정 이력에서 저장한 매핑을 확인하고 엑셀로 내보낼 수 있습니다.

후보 선택 → ‘이 IRDI로 확정’ → 검토자·선정 근거 입력 → ‘확정하고 저장’ 순서로 기록합니다. ‘확정 이력’에서 새 기록과 이전 기록을 함께 확인하고 Excel/CSV로 내보낼 수 있습니다. 앱을 다시 실행해도 기록은 남습니다.

원본 항목명·적용 조건·해석된 검색어·IRDI·표준 명칭·정의·단위·데이터형·사전 버전·검토자·근거·확정 시각을 PC에 저장합니다. 검색 조건이나 사전이 바뀌면 다시 검색해야 하며 사용 중단 속성은 신규 확정할 수 없습니다.

확정 이력 삭제기록별 ‘이력 삭제’에서 항목명과 IRDI를 확인한 뒤 해당 기록 1건을 삭제합니다.

‘확정 이력’에서 삭제할 기록 오른쪽의 ‘이력 삭제’를 선택합니다. 확인 창의 항목명·IRDI·검토자·확정 일시를 확인한 뒤 삭제합니다.

같은 항목이나 IRDI가 여러 번 저장되어 있어도 선택한 기록 1건만 삭제합니다. 취소하면 기록을 유지합니다.

삭제한 기록은 복구할 수 없습니다. 필요한 기록은 먼저 ‘이력 내보내기’로 보관하세요. 사전 속성과 이미 내보낸 엑셀 파일은 변경되지 않습니다.

여러 데이터 항목의 검색 후보를 엑셀 파일로 확인하는 기능입니다.

입력 파일 작성 기준

첫 행은 열 이름, 두 번째 행부터는 검색할 데이터를 입력합니다.

항목 제목을 선택하면 상세 설명이 표시됩니다.

미등록 한국어 표현도 자동 해석하므로 새 표현이 많으면 오래 걸릴 수 있습니다. ‘검색 취소’로 중단하면 부분 결과를 저장하지 않습니다. 배포 ZIP의 검색항목_예제.xlsx처럼 소량으로 먼저 시험합니다.

후보 비교에서 입력 항목과 적용 조건은 묶어서 한 번만 표시합니다. 표준 후보명 바로 오른쪽에서 한국어·영문 정의를 함께 읽을 수 있습니다. IRDI를 누르면 검토 근거의 단위·형식과 검토 근거로 이동합니다. 한국어는 비공식 참고 번역이며, XML 한국어 원문과 원문 확인 필요 상태를 구분합니다.

입력 정보는 항목당 한 줄입니다. 모든 항목에서 빈 선택 열은 제외하고 나머지는 미입력으로 표시합니다. 표준 사전에 정보가 없으면 사전 미기재로 표시합니다.

입력당 상위 5개 후보까지 출력하며 후보가 없는 항목도 남습니다. 원본 필드·후보 순서·번역 출처는 숨겨진 전체 데이터 시트에 보존합니다. Excel의 시트 숨기기 취소로 확인할 수 있습니다. 병합된 검토 시트에는 정렬 필터가 없습니다. 일괄 결과는 자동 확정된 매핑이 아닙니다.

입력 및 저장 오류의 처리빈 항목명·계산값 없는 수식·엑셀에서 열린 저장 파일을 확인합니다.

저장을 취소해도 일괄 검색 결과는 앱에 남습니다. ‘검색 결과 저장’에서 다시 저장합니다. 앱을 닫으면 저장하지 않은 결과는 사라집니다.

BASIC CSV는 IrdiPR·PreferredName·Definition·DataType 열이 있는 속성 표를 읽고, 함께 있는 단위·클래스·직접 연결·동의어·제한 값목록 표를 연결합니다. 속성 CSV만 가져오면 함께 제공되지 않은 단위·분류 정보는 확인할 수 없습니다. 사용 중단 정보는 CSV에 없어 미확인으로 표시합니다. 클래스별 추천 값·제약 조건과 상속 관계는 전개하지 않습니다. 클래스용 키워드는 속성 동의어로 취급하지 않습니다.

폴더와 ZIP의 식별원본이 바뀌면 폴더 또는 ZIP을 다시 연결합니다.

폴더와 ZIP 모두 실제로 읽는 사전 파일의 경로·내용 해시와 자료 종류로 식별합니다. 폴더 안의 다른 사업 문서나 PPT는 읽지 않습니다.

변경된 자료를 반영하려면 폴더 또는 ZIP을 다시 가져옵니다. 같은 자료는 재분석을 생략하고, 실패한 가져오기는 기존 사전과 이력을 유지합니다.

확정 이력 또는 계획서 비교·검증의 확정 결과 내보내기에서 ‘AASX 복사본에 적용’을 선택합니다.

① 원본 AASX 선택 → ② 실제 변경 위치와 보류 항목 확인 → ③ 전체 위치 적용 확인란 선택 → 새 이름으로 저장 순서입니다. 기존 semanticID·검토자·선정 근거·단위 확인 상태를 먼저 보완합니다. 대상 파일이 비어 있으면 선택한 AASX를 사용하고, 다른 대상 파일이 지정되어 있으면 중단합니다.

원본을 덮어쓰지 않습니다. 내부 JSON 모델은 EXE에 포함된 변환 도구로 XML로 바꾸며, XML 모델은 그대로 사용합니다. 첨부파일 경로·내용·연결 정보와 모델 내용 보존을 검사한 뒤 복사본과 HTML/JSON 검사 결과를 저장합니다. 서버·Python 별도 설치·온라인 AI는 필요하지 않습니다.

일치하는 semanticId와 연결된 ConceptDescription ID가 함께 변경됩니다. 개념 정의의 기존 명칭·설명은 유지하므로 새 IRDI의 의미와 대조해야 합니다. 여러 키의 semanticId, 다른 참조에서 재사용된 ID, 개념 정의 ID 충돌, 서명된 패키지, 여러 모델을 담은 패키지는 중단합니다. JSON은 AAS 3.0 변환 지원 범위, XML은 AAS 3.0/3.1 환경을 지원합니다.

표시되는 ‘자동 검사 통과’는 Package Explorer 재열기 확인과 다릅니다. 새 AASX를 Package Explorer에서 열고 모델·첨부자료를 확인한 뒤 사용합니다. 빈 단위·속성값·데이터형은 그대로 유지합니다.

번역 모델과 배포ZIP 전체를 풀어 EXE 옆의 models 폴더를 함께 배치합니다.

배포 ZIP 전체를 풀어 EXE 옆의 models 폴더를 함께 배치합니다. EXE만 복사하면 번역 모델을 찾을 수 없습니다. 모델과 실행 도구는 약 2.55GB입니다. 서버·API 키·인터넷 연결 없이 PC의 CPU에서 번역합니다. 번역이 실패해도 원문 정의를 확인할 수 있습니다. 수치가 달라지거나 문장이 중간에 끊긴 결과는 저장하지 않지만, 모든 의미 오류를 검출하는 것은 아닙니다.

기존 사전에 추가된 언어별 원문을 읽으려면 사전 파일 또는 폴더를 다시 연결합니다. 일괄 검색 파일의 definition은 원문이며, preferred_name과 short_name 열도 함께 제공합니다. 한국어 정의는 상세 화면과 엑셀 일괄 결과에서 제공합니다. 새 문장이 많으면 번역에 시간이 걸리며 진행 중 취소할 수 있습니다. 번역 실패 시에도 영문 원문과 후보는 남습니다.

미지원 기능CDD 검색·신규 AAS 모델 설계·자동 승인·단위 변환은 아직 지원하지 않습니다.

임베딩·대화형 AI, IEC CDD 통합 검색, 신규 AAS 모델 설계·생성, 자동 승인, 단위 값 변환, 이력 병합, 클래스 관계 전체 전개는 포함하지 않습니다. 기존 AASX의 식별자 변경 복사본은 생성할 수 있습니다.

개발계획서 비교·검증

계획서의 기존 IRDI와 독립 검색 결과를 비교하고 사용자 검토를 기록합니다.

검색 비교와 최종 판단을 분리

기존 IRDI는 검색 입력에 사용하지 않습니다. 상위 후보와 원문 정의를 비교한 뒤 사용자가 판단합니다.

항목 제목을 선택하면 상세 설명이 표시됩니다.

01 계획서 선택과 추출 확인문서 표 구조에 따라 누락될 수 있으므로 원문과 추출 내용을 확인합니다.

왼쪽 ‘계획서 비교·검증’에서 HWPX·HWP·XLSX를 선택합니다. HWP는 유형 → idShort → 설명 → 예시 → semanticID 순서의 표를 지원합니다. 일반 HWPX는 항목 이름(idShort)과 semanticID 머리글을 기준으로 추출합니다. 다른 양식은 ‘XLSX 양식’을 사용합니다.

자동 추출은 문서 전체를 보장하지 않습니다. 원문과 추출 행 수를 확인하고 누락 행은 추가합니다. 자체 정의 URL/URN도 ECLASS 대체 후보를 검색합니다. IDTA·CDD는 기본 제외됩니다. 기존 작업은 ‘자체 정의 포함’으로 대상을 추가합니다. 공통 장비명은 행별 장비가 비어 있는 항목에 적용됩니다. 결과의 우선 확인 필터로 검색 실패·후보 없음·조건 충돌·후보 차이를 먼저 확인합니다. 항목명·idShort·기존 ID·설명·장비·단위·데이터형과 후보 목록이 모두 같은 항목은 근거를 입력하고 동일 조건 묶음에 판단을 적용할 수 있습니다. 검색 결과가 일관되어도 의미 적합성이 자동 확정되는 것은 아닙니다.

02 검색 항목과 조건 수정검색 항목명과 적용 조건을 수정하고 확인란을 선택합니다.

행을 선택하면 검색 항목명·기존 IRDI·장비·단위·설명 등을 수정할 수 있습니다. ‘수정 적용’을 누른 뒤 확인란을 선택합니다. 수정하면 이전 검증 결과가 초기화됩니다. 검색 항목명에는 한국어 항목 이름을 입력하고 기존 IRDI를 섞지 않습니다.

03 비교 결과와 최종 판단상위 5개 검색 결과·개정 차이·검색 실패를 구분합니다.

항목명 단독과 조건 추가 검색의 상위 5개를 비교합니다. 기존 IRDI는 검색 후 대조에만 사용합니다. 상위 5개에 없다는 결과는 전체 사전에 없다는 뜻이 아닙니다. 다른 개정만 존재·검색 실패·사용 중단은 별도 확인합니다.

후보 순위와 자동 검사 의견은 의미 적합성의 최종 판정이 아닙니다. 원문 정의를 비교한 뒤 유지·대체·추가 확인을 선택하고 선정 근거와 함께 ‘검토 저장’을 누릅니다.

04 저장과 내보내기마지막 작업은 PC에 보관되며 HTML·Excel로 별도 저장할 수 있습니다.

마지막 작업과 검토 판단은 사용자 데이터 폴더의 plan-review.json에 저장되며 다음 실행 시 복원됩니다. 원본 계획서와 기존 확정 이력은 변경하지 않습니다. 여러 문서의 결과를 보관하려면 각각 HTML 또는 Excel로 내보냅니다.

모든 처리와 검색어 해석은 PC 내부에서 수행합니다. 로컬 모델이 준비되지 않았거나 해석에 실패하면 검색 실패로 표시합니다. 중단한 검증은 일부 결과임을 표시합니다.
